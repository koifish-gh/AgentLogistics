AGENTLOGISTICS

智能仓储机器人调度系统

本系统在一张可复现的网格仓库中调度多台机器人完成取货与送达。仿真内核负责路径、碰撞与订单状态；常规分配由确定性规则完成。仅当出现故障、通道对向或订单突发时，系统才调用大模型，并把该次决策的原因保留在界面上。

问题与目标

多台机器人共用同一组窄通道。它们会在取货点与送货点之间交会，也会因故障停在通道上，或在短时间内接收一批新订单。若每一格移动都询问大模型，演示难以连续进行，决策依据也不易核对。

仿真必须可信

地图、路径、碰撞和订单状态由 Rust 内核计算。相同版本、相同种子和相同命令序列，得到相同的世界状态与指标。

常规调度必须可解释

没有关键事件时，系统按公开的代价分配订单，不访问模型。代价由坐标和已完成单数算出。

例外必须看得见

故障改派、对向让路和订单突发会在顶栏标出对应 Agent，并在决策页留下说明。模型失效时退回同一套规则。

仓库如何运转

默认演示为 24×16 的网格、5 组双深货架、5 台机器人。下图是布局示意，不是某一时刻的运行快照。

蓝色点表示取货点，橙色点表示送货点，折线表示一条沿通道行走的路径。坐标原点在左上角，x 向右，y 向下。货架格不可通行，也不能作为取货点或送货点。

故障停机

订单

待分配→ 已分配→ 运输中→ 已完成

取货与送达不额外占用时间。到达取货点后订单进入运输中，到达送货点后记为完成，并累计该单从创建到完成的 tick。

一个时间步里发生什么

时间是离散的。界面上的速度只改变两步之间的等待，不改变一格的含义。1 倍速大约每 0.9 秒推进一步。

  1. 1处理当前位置

    已经到达取货点或送货点的机器人先完成取货或送达，再为仍空闲的机器人安排任务。

  2. 2规划下一步

    路径由四方向 A* 生成，一格为一步。规划会考虑其他机器人当前占用，但进入格子前仍须通过安全检查。

  3. 3全体同步移动

    每台执行中的机器人本步最多移动一格。检查顺序逐轮轮换，避免编号小的机器人始终优先。

  4. 4记账

    记录到达、等待和热力图。连续等待满 3 步会写入「等待绕行」，并在随后的步骤中尝试重规划。

三条约定保证不相撞

本步开始时所在的格子，以及本步选定的目标格，都会被预留。

  • 两台机器人不能进入同一格。
  • 面对面的两台不能在同一步交换位置。
  • 后车不能在同一步跟随前车进入其刚刚离开的格子。

无路时保持原状

目标不可达时机器人不移动，订单也不会被记成完成。封锁会立即作废经过该格的旧路径；机器人脚下的格子不能被改成障碍。

派单如何比较候选人

演示运行时，仿真自身的自动派单被关闭，避免与 Agent 重复分配。日常订单由 Agent 内的本地规则处理。规则与决策页上的候选对比使用同一公式。

代价 = 到目标的格数 + 已完成单数 × 4去取货时，格数是当前位置到取货点的曼哈顿距离；已经取到货时，按剩余送货路径计算。

下面是演算示例，不是某一次运行的记录。

候选人到取货点已完成代价结果
R25 格3 单5 + 12 = 17距离更近，但负载更高
R48 格0 单8 + 0 = 8本轮分给 R4

因此，少完成订单的机器人可以优先于单纯距离更近的机器人。这个系数 4 是可解释的均衡基线，不表示全局最优。

nearest

只比较到取货点的实际路径长度。演示主流程不使用这一策略自动派单。

balanced

路径长度再加已完成单数乘 4。与上面的代价同一思想。

manual

仿真不再自动派单。界面上的「立即派单」随之无效。指定某一台机器人，需要在订单页手动分配。

从界面到仿真的一条链路

浏览器不直接改写仓库。操作先到达本机 8788 端口上的 Agent，再由 Agent 向仿真进程发送 JSON 命令。

数字孪生、六个页面和场景注入。播放、单步和顶栏状态在所有页面保持可用。

Agent

读取世界摘要，在本地规则与一次模型调用之间选择，然后请求仿真前进一步。

状态的唯一来源

Rust 仿真

执行路径规划、碰撞检查、故障和指标统计，返回新的世界快照。

没有关键事件

若不存在新故障、通道对向，也不存在空闲机器人与待分配订单，本步只发送 step。机器人沿已有路径移动一格，顶栏保持「运行中」。

若只是普通待分配，系统调用本地规则完成分配，仍然不访问模型。分配之后再推进一步。

出现三类事件之一

故障、通道对向，或刚刚由界面注入的订单突发，会把压缩后的状态和允许使用的工具提交给模型。顶栏变为红色，并显示对应 Agent 已经等待的秒数。

模型超时、额度不足或没有给出有效动作时，同一轮改由本地规则完成，决策说明中会写明原因。演示不会因此停止。

每一步返回的快照用于重绘地图、表格和曲线，并写入服务侧会话文件。刷新页面不会丢失当前运行；Agent 服务重启后也可以接上上次的仿真世界。

三类关键事件

场景按钮先改变仓库。模型在下一次需要决策时才被调用。待处理订单数量增加本身不会被当作订单突发。

机器人故障

注入之前

R1 正在运送订单。其未完成任务仍绑定在这台机器人上。

→
异常 Agent

R1 停在原地并成为障碍。订单退回待分配，由其他空闲机器人接替，优先选择已完成单数更少者。R1 不会自动恢复。

取货前，订单回到原取货点重新分配。取货后，货物留在故障位置或其相邻格，由其他机器人接运后再送往原目的地。这是仿真中的交接假设，不表示机械臂具备卸载能力。只有操作者注入「修复故障」后，该机器人才能重新空闲。

通道对向

形成对向

两台机器人的下一步互相指向对方当前位置，通道无法同时通过。

→
路径 Agent

只重规划剩余路程更长的那一台，让它避开正对面的一格。对面机器人以及同向跟随的机器人保持原路径。

订单突发

手动注入

操作者指定数量，系统按种子在可通行且相互可达的格子上生成一批新订单，并打上突发标记。

→
派单 Agent

下一步若仍有空闲机器人，模型负责把这批订单分散出去。每个空闲机器人最多接收一张，避免集中到同一台。

总览：确认全仓正在运行

上方六项计数给出机器人总数、运行中、订单总数、已完成、待分配和故障机器人数。中央地图支持等距、俯视和侧视，左键旋转、右键平移、滚轮缩放。路径、订单点、热力图、拥堵、故障和坐标可以分别开关。

地图上方的一行文字在发生派单、让路或故障改派后换成该次说明。右侧为吞吐量、平均完成时间、利用率和待处理订单。底部默认打开场景事件，也可切换到机器人、订单、日志、决策摘要和趋势。

机器人管理：核对一台机器人

可按全部、运行中、空闲和故障筛选，或按编号与订单号搜索。卡片列出坐标、当前任务、取送货点和利用率。利用率等于该机器人处于任务中的 tick 除以已运行 tick，系统不提供电量。

中间简图为俯视，图标位置对应真实坐标。右侧详情分为基本信息、任务、后续最多十格路径，以及与该机器人相关的最近事件。

订单调度：核对一张订单

状态分为待分配、已分配、运输中和已完成。另有一类异常，表示货物仍停留在故障后的接运位置。表格给出优先级、取送货点、执行机器人和剩余 tick。剩余 tick 等于剩余路径格数。

对待分配订单可以指定一台空闲机器人，该操作不经过模型。创建订单时回到总览地图，依次选择取货点与送货点；货架格和同一格子会被拒绝。

Agent 决策：核对一次选择

页面顶部按事件发现、分析、选定方案和执行四步展开。简图同时标出货架、机器人、取送货点、规划路线和封锁。候选对比列出每台机器人的状态、格数和综合代价，点选后可在图中定位。

决策原因把距离、已完成单数和通道情况分开书写。日志按 tick 保留分配、让路和改派。尚未运行时这些区域为空，不表示系统缺少决策能力。

数据分析：汇总这一次运行

首行给出完成订单、完成率、平均完成时间、全队利用率和当前故障。其下是分机器人的利用率曲线，以及由停留 tick 绘制的仓库热力图，货架不参与着色。

订单状态、平均取货时间、平均送达时间、累计行驶格数和累计等待另行列出。异常统计区分机器人故障、道路封锁、道路恢复和订单突发。订单突发的次数只统计界面中成功注入的次数。

系统设置：参数与连接

可调整随机种子、调度策略、重置后是否自动生成订单、生成数量和仿真速度。应用这些仿真参数会重置世界。地图视角和图层开关立即生效，并保存在本机。

连接卡片显示服务地址、连接状态、当前 tick、数据来源和最近一次错误。页首「感知仓库 · 理解任务 · 智能决策 · 协同执行」是界面题词，不是四个独立子系统。

演示顺序、结果与边界

建议的观察顺序

  1. 开始运行。顶栏为「运行中」，机器人沿路径移动，此时不询问模型。
  2. 注入订单突发。顶栏转红，派单 Agent 分配这批新订单。
  3. 封锁一段通道，或等待对向形成。路径 Agent 只调整路程更长的一台。
  4. 注入一台故障。该机器人停止，订单被改派，且不会自行恢复。
  5. 在地图上创建一张订单，确认货架不能作为端点。
  6. 打开数据分析，用热力图和完成单数结束。这些数字属于本次运行。

观察过程中不要使用「重置世界」，否则当前仿真和本机保存的进度会被清除。

可以核对的结果

当前 tick、完成与待处理订单、故障机器人数、每 100 tick 的吞吐量、平均完成 tick、利用率、总行驶格数、总等待 tick、剩余路径和热力图停留次数，均来自仿真内核。

当前没有覆盖的部分

系统不模拟电量、充电、加速度、车身体积和真实机械取放。调度规则是可解释基线，不是全局最优。模型不决定每一格移动。故障不会自动消失。本系统尚未连接真实仓库，也不支持多用户同时操作。

单宽通道被占用、必经之路被空闲机器人堵住或目的地被封锁时，机器人可能持续等待。仿真保证不相撞，不保证每一张订单最终都能完成。

演示入口为 http://127.0.0.1:8788/ 。模型密钥仅保留在运行该服务的本机，不进入讲解材料。
