# AgentLogistics 项目总述

给 PPT 使用。只写当前演示里真实存在的能力，不要另加电池、充电、机械臂或「每一步都由大模型决策」。

## 一句话

多台仓储机器人在同一张地图上取货送货。仿真负责把路算对、把碰撞拦住；平时按规则派单，只有故障、通道对向、订单突发才调用大模型，并且能在页面上看到改派或绕行的原因。

## 做这个项目要解决什么

仓库通道窄，多台机器人会迎面堵住，也会突然故障，或一下子进来一批订单。如果每走一格都问模型，演示又慢，也说不清模型做了什么。

所以拆成三层：

- 仿真内核把世界算对，同一套种子和命令可以重放。
- Agent 只处理规则说不清的例外。
- 网页把机器人、订单、路径和决策实时显示出来。

这是课程演示用的网格仿真，不是真实仓库控制系统。

## 项目结构

演示时浏览器只连 `http://127.0.0.1:8788/`。这个进程同时提供网页和 Agent 接口，并在后台拉起 Rust 仿真。

├── agent/                Node.js Agent

`scripts/server.mjs` 是只连仿真、不带 Agent 的旧接口，默认端口 8787。汇报演示不要用它。命令行里还有一套连续多 Agent 模式，网页演示不走那条路。

## 完整链路

一次「开始运行」从页面走到仿真，再回到页面，顺序是固定的。

1. 浏览器打开 8788，加载 `web/`。`store` 启动时：服务里已有跑过的世界就用服务上的；否则用本机上次保存的显示副本；都没有才重置成默认仓库。
2. 点开始后，前端按速度定时推进。1x 大约每 0.9 秒一步，4x 更快。速度只改页面间隔，不改仿真里一格的含义。
3. 每一步先看要不要决策。没有新故障、没有对向、也没有「空闲车 + 待分配订单」时，只发 `step`，机器人沿已有路径走一格。
4. 需要决策时，前端改调 `POST /api/agent/decide`。普通待分配走本地规则，不访问模型。只有故障、通道对向，或刚刚注入的订单突发，才把压缩后的状态和允许使用的工具发给模型。
5. 模型要在限定工具里做出动作：故障用 `assign_order`，对向用 `replan`。超时、失败或没有有效动作，就改用本地规则，并在说明里写明。
6. 这一轮分配或让路之后，Agent 再让仿真 `step` 一格。仿真检查碰撞、更新订单和 KPI，返回新的世界快照。
7. 页面用这份快照重画地图、表格和曲线。同时把世界写入 `agent/session.json`。浏览器另存一份显示用记录，刷新不丢；服务重启后由快照接上。

场景按钮不直接问模型。它们先改世界，下一步决策再看要不要叫模型：

- 机器人故障：`inject_fault`。订单退回待分配，下一步由异常 Agent 改派。车保持停机。
- 修复故障：`repair_robot`。只有人手动点了才会恢复。
- 订单突发：`generate_orders`，并打上突发标记。下一步有空闲车时，派单 Agent 问模型。待处理订单一多本身不会打这个标记。
- 单点封锁、路段封锁、道路恢复：`set_blocked`。封锁立刻作废经过该格的旧路径。不能封锁机器人脚下。对向形成后，下一步才由路径 Agent 处理。
- 创建订单：在地图上点取货点、送货点，或手填坐标，再按数量重复 `add_order`。货架格和同一格会被拒绝。

手动把某一单分给某一台，走订单页的 `assign_order`，不经过模型。

## 仓库里实际在模拟什么

默认演示地图是 **24×16**，**5 组双深货架**，**5 台机器人**。货架是障碍，机器人走货架之间的通道。坐标原点在左上角，x 向右，y 向下。

时间是离散 tick。每一步先处理派单和到达，再让所有机器人最多移动一格。

机器人状态：空闲 → 去取货 → 去送货 → 空闲。故障是单独状态，停在原地，并变成别人不能穿过的障碍。一台机器人同时只拿一单。

订单状态：待分配 → 已分配 → 运输中 → 已完成。取货点和送货点必须是可走格子，不能点在货架上，也不能是同一个格子。

路径用四方向 A*，一格算一步。移动时预留格子，禁止两台车重叠、对向交换、同一 tick 跟车钻进同一格。连续等满 3 tick 会记「等待绕行」，并尝试重规划。

派单基线有三种，演示运行时会切到 **manual**，避免仿真自己派单和 Agent 抢单：

- nearest：离取货点更近的优先。
- balanced：距离加上已完成单数 × 4，少干活的优先。
- manual：仿真不再自动派单。页面上的「立即派单」此时无效；日常单由 Agent 的本地规则分配，指定某一台要到订单页手动分配。

本地规则和候选对比用的都是同一条代价：**到目标的格数 + 已完成单数 × 4**。距离是坐标算出来的，不是手填的评分。

## Agent 什么时候出手

平时机器人赶路、普通待分配订单，**不调用模型**，由本地规则分配，顶栏显示「运行中」。

只有下面三类事件才问模型。问的时候顶栏变红，并显示是哪一个 Agent、已经等了几秒。模型超时、额度不够或没有给出有效动作时，自动退回本地规则，决策说明里会写明。

| 事件 | 谁处理 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| 机器人故障 | 异常 Agent | 把没送完的订单改派给其他空闲机器人，优先已完成单数更少的 | 不自动修复，故障车保持停机 |
| 通道对向 | 路径 Agent | 只让剩余路程更长的那一台避开正对面的一格 | 不改对面那一台，也不改同向跟随的车 |
| 订单突发 | 派单 Agent | 把这一批新订单摊到不同空闲机器人上 | 不是看到待处理订单多就自动当突发 |

故障车要等操作者注入「修复故障」才恢复。取货前的订单退回原货位重新派；取货后货物留在故障位置附近，由其他机器人接运再送原目的地。这是仿真里的交接假设，不要讲成机械臂卸货。

## 从前端看整个界面

所有页面共用一个外壳。

左侧栏从上到下：机器人标志、名称 AgentLogistics、副标题「智能仓储机器人调度系统」、标语「让每一次调度，都更智能」。中间是六个入口。底部是一块「智能仓储控制台 / 实时监控 · 动态调度」，再下面一行连接状态，连上后显示「Agent 大脑 · 已连接」。后端没连上时，页面会改用演示快照，并标明这不是实验结果。

顶栏左边是当前页标题和一行说明，旁边是「重置世界」。中间五个状态：连接或运行、机器人数、订单数、完成数、异常数。正在问模型时，第一个状态变红，写成「异常 Agent / 路径 Agent / 派单 Agent 询问模型 Ns」。右边是当前 Tick、0.5x 到 4x、播放、单步、重置图标、深浅色和设置。顶栏这些控制在每个页面都在，不需要回到总览才能暂停。

### 总览

看整仓是否在跑。上面六张计数卡：机器人总数、运行中、订单总数、已完成、待分配、异常。

中间左侧是「仓储数字孪生」。标题旁写着地图尺寸、货架组数，以及红色的「左键旋转 · 右键平移 · 滚轮缩放」。地图上可以开关路径、订单点、热力图、拥堵、故障和坐标。视角有等距、俯视、侧视；放大、缩小、适应仓库、恢复视角和全屏叠在「侧视」下面。图例包括货架、取货点、送货点、按机器人区分的路径、拥堵和故障。地图上方一行字会换成最近一次派单、绕行或故障改派的说明。

右侧两块：「运行指标」是吞吐、平均完成时间、利用率、待处理订单，各带一条短趋势；「仿真控制」里有运行状态、策略、订单生成自动或手动、种子、速度，以及开始、单步、重置、立即派单、生成订单、创建订单。

底部默认打开「场景事件」，可注入故障、修复、订单突发、单点封锁、路段封锁和道路恢复。路段封锁要回到地图上点起点和终点。另外五个标签：机器人状态、订单动态、事件日志、Agent 决策摘要、性能趋势。创建订单时，地图上浮出数量和取送货坐标，点格子或手填都可以。

### 机器人管理

看某一台车。上面按全部、运行中、空闲、故障筛选，数量写在按钮上，也可以搜编号或订单号。

左侧是机器人卡片：颜色、状态、利用率、坐标、当前任务、取货点和送货点，以及定位按钮。利用率是这台车有任务的 tick 除以已运行 tick，没有电量。

中间是俯视仓库简图，图标位置就是真实坐标。图层可单独关：机器人、路径、取货点、送货点、封锁、货架。点图上的车和点卡片是同一台。

右侧详情四个标签：基本信息（坐标、状态、利用率、行驶格数、累计完成单数、预计剩余 tick、任务路线）、任务信息（订单号、优先级、取送货点、剩余路径）、运行轨迹（接下来最多列出 10 格）、历史记录（这台车最近的仿真事件）。

### 订单调度

看单，而不是看车。上面六张卡：全部、待分配、已分配、运输中、已完成、异常。这里的异常是「货物还在故障接运位置」，不是机器人故障数。

表格可按状态筛选，按优先级或订单号排序，搜订单号，每页 10 条。列有订单编号、优先级、状态、取货点、送货点、分配机器人、预计完成、操作。预计完成是剩余路径格数，一格对应一个 tick。待分配的单可以点「分配」，选择一台空闲机器人，这条不经过模型。点「创建订单」会切回总览地图去选点。点一行可看详情；定位会把总览地图移到这张单的取货点。

### Agent 决策

解释最近一次为什么这样分。顶上四步：事件发现、Agent 分析、决策方案、执行调度，做到哪一步会高亮。

左侧是调度简图，画出货架、机器人、取送货点、规划路线和封锁。点「在总览地图查看」会跳回总览并定位这张单。简图下面是候选对比：每台机器人一行，显示状态、到目标的格数和综合分。代价就是「格数 + 已完成单数 × 4」。点一台，简图改标它。再下面是决策说明，关键事件发生后这里是模型或规则写下的那一句。

右侧三块：当前决策（订单、取送货坐标、分给了谁、剩余格数）、决策过程（发现事件、评估机器人、选择方案、规划路径、执行调度）、最近决策记录。

底部两块：决策原因把距离、已完成单数、通道冲突和综合分拆开写；决策日志按 tick 记下分配、让路和故障改派。没有运行过时，这些区域是空状态，不要截成「系统没有决策能力」。

### 数据分析

只统计这一次运行。未连接后端时顶部会出警告，曲线不能当实验结果。

第一排五张卡：完成订单和吞吐、完成率、平均完成时间、全队利用率、当前故障和累计故障次数。

下面两张图：每台机器人的利用率趋势；仓库占用热力图，颜色来自每个格子被停留的 tick，货架不参与着色。

再下面三块：订单状态环形图，含待分配、已分配、运输中、已完成，有接运时多一类「待接运」；订单处理效率，分平均取货、平均送达、累计行驶格数、累计等待 tick；异常统计，分机器人故障、道路封锁、道路恢复、订单突发。订单突发的次数等于界面里成功注入的次数，不是待处理订单的数量。

最底是最近仿真事件，新的在上，例如订单分配、完成取货、路径重规划、等待绕行、故障和修复。

### 系统设置

页首一行「感知仓库 · 理解任务 · 智能决策 · 协同执行」，是界面口号，不是四个独立系统。

四张卡：

- 仿真参数：种子、策略、重置后是否自动生成订单、生成数量、速度。点「应用仿真参数」会重置世界。
- 地图显示：默认等距、俯视或侧视，以及路径、订单点、热力图、拥堵、故障、坐标开关。立刻生效，记在本机。
- 界面偏好：浅色或深色，标准或紧凑，以及恢复默认显示。
- 后端连接：服务地址、是否连上、当前 Tick、数据来源、最近一次错误。

## 建议的演示顺序

按这个顺序讲，观众能分清「规则在跑」和「模型刚介入」。

1. 打开总览，开始运行。机器人在赶路，顶栏是「运行中」，此时没有问模型。
2. 注入订单突发。顶栏变红，出现派单 Agent。讲完再看决策页里的分配说明。
3. 封锁一段路，或等到两台车对向。路径 Agent 只改路程更长的那一台。
4. 注入一台机器人故障。它停住，订单被改派，车不会自己修好。需要的话再点修复。
5. 在订单页或总览里手动创建一单，点地图选出取货点和送货点。
6. 打开数据分析，用热力图和完成单数收尾。这些数来自本次运行。

不要在演示中途点「重置世界」，它会清空当前仿真和本机保存的进度。

刷新页面不会丢掉这次运行。Agent 服务重启后也能接上上次仿真世界。场景操作记录以浏览器里看到的为准。

## 数字怎么讲才站得住

可以讲，因为它们来自仿真：

- 当前 tick、完成单数、待处理单数、故障机器人数。
- 每 100 tick 完成多少单、平均完成用了多少 tick。
- 利用率：有任务的时间占已运行 tick 的比例。
- 总行走格数、总等待 tick。
- 某台车剩余路径长度、到取货点的格数、已完成单数。
- 热力图上的停留次数。

不要讲成系统已经具备的能力：

- 电量、充电、加速度、车身体积、真实机械取货。
- 全局最优调度。balanced 和本地规则只是可解释的基线。
- 模型一直在线，或每走一步都是模型决定的。
- 待处理订单一多就自动叫派单 Agent。只有手动「订单突发」才会。
- 故障会自动消失。
- 这套界面已经接到真实仓库或支持多人同时操作。

## 已知边界

单宽通道、空闲车堵住必经之路、目的地被封死时，机器人可能一直等待。仿真保证不相撞，不保证每一单最终都能送完。

模型不可用时，故障改派、让路和突发分配仍按本地规则执行，演示不会卡住，但那一轮就不是模型决策。

不同软件版本之间不保证回放文件逐位一致。同一版本、同一初始种子、同一串命令，得到的世界状态、事件和指标相同。
