已阅读本文件夹唯一的原始资料《AgentLogistics 智能仓储机器人调度.pdf》：Rust 核心负责地图、运动、订单、碰撞检测和故障；Agent 做决策；JS 展示状态及 KPI；评估支持固定种子回放。

源码、构建缓存、演示输出、开发工具均放在此项目目录，没有修改原 PDF 或系统 PATH。

## 模型约定

- 采用离散时间步和领域事件日志。一个 `step:1` 先自动派单、服务当前位置、规划，随后同步移动，最后服务到达点并统计热力图。每步最多移动一格；取放货暂不消耗额外时间。
- 单机器人最多承接一个订单，容量为一单。先按优先级降序、创建时间和 ID 升序挑选订单。
- `nearest` 使用 A* 到取货点的实际距离；`balanced` 使用该距离加 `4 × 已完成订单数`，是可解释的历史工作量均衡基线，并非全局最优调度。
- 碰撞检查预留所有机器人本步开始的位置及已选目标格，禁止同格、对向交换和同一步跟车进入。机器人检查次序每步轮换，减少固定 ID 的抢占优势。
- 规划考虑其他机器人当前占用；处于执行任务状态的机器人暂占目标格时允许先规划，真正进入前仍须通过移动安全检查。
- 连续等待达到 3 步时写入 `robot_waiting`，后续每步尝试绕行。无路时不移动，不穿越障碍，不虚构任务完成。
- 通道封锁立即清除经过该格的旧路径，下一步重新规划；解除后允许恢复。机器人当前位置不可被改为障碍。
- 故障机器人原地成为障碍，任务回到 pending。取货前重新去原货位；取货后在故障位置记录 `recovery_from`，由其他机器人在该位置或四邻格接运，再去原目的地。**接运是仿真中的可卸货/人工辅助交接假设**，不表示真实机械臂能力。
- 故障货物按已卸载缓存处理，即使原机器人修复并离开，货物仍位于记录的位置；接运成功后才清除该记录，避免货物瞬移回原货位或重复交付。
- 无电池、加速度、碰撞体积、充电或多订单队列。地图障碍格不能直接作为取放货点，需使用相邻可通行的服务格。

## 确定性与回放

固定 SplitMix64 PRNG 和有序容器；A* 与派单平局规则固定。相同版本、初始 seed 和有序命令产生相同世界状态、事件和 KPI。
`--record` 在正常 stdin 结束时保存 `{version:1,seed,commands}`。可解析但业务失败的命令也记录；解析失败行不记录，因其没有业务影响。
`--replay` 执行命令后输出最终 get_state 结果。自定义地图通过记录的 `reset` 命令复现。
录制文件只在正常结束时写出，非崩溃恢复日志；不保证不同软件版本之间逐位一致。

- Rust 自动测试：A* 与 BFS 在 256 张障碍布局上核对；起终点/无路边界；完整订单和 KPI；取货前及取货后故障恢复；封路绕行及解除恢复；交叉车流；单通道迎面安全等待；优先级与人工控制；输入失败无状态副作用；相同 seed 完整状态回放；8 个 seed 各 150 步、30 订单的安全与订单归属约束。
- CLI 集成：实际进程通信，录制/重放最终 JSON 完全一致，非法输入后继续服务，输出路径边界，默认 20 单故障演示全部完成。
- HTTP/SSE 集成：状态、下单、推进、领域事件、初始和变更快照推送、并发推进顺序、错误码和本地跨域。

## 已知边界

保守格点预留只保证移动安全，不保证所有订单最终完成。单宽走廊、空闲机器人占据必须通过的瓶颈、已封锁目的地等可能持续等待；需 Agent 调整环境/任务或后续增加停车点、让行和时空协同规划。
目前没有任意移动空闲机器人的工具，所以通道被空闲机器人占用时可给它合法取放货任务使其离开，或用 reset 重新组织场景；不要通过直接改坐标绕过安全模型。
事件保留在内存且快照包含全部事件；适合课程演示规模，长时间运行应再增加环形事件存储、分页及快照裁剪。SSE 慢消费者会断开，重连获取最新状态。
当前采用时间步驱动而非带时间优先队列的事件跳跃引擎；大规模性能优化不在本次基线中。
